## Содержание лекции

### Алгоритмы вокруг нас

Оплата картой, обработка фотографии, подбор музыки, маршрут в навигаторе —
за каждым действием стоит алгоритм: входные данные, правила обработки,
результат. Разные на вид задачи часто сводятся к одним и тем же действиям
с данными: найти, связать, упорядочить или сократить.

Готовые функции языка не снимают трёх вопросов: какую структуру данных
выбрать, сколько операций сделает решение на большом входе и как доказать,
что ответ верный. Пример со слайда: проверка `x in список` перебирает
элементы по одному, проверка `x in множество` находит элемент сразу.

### Алгоритмическая секция

Алгоритмическая секция — часть собеседования, около 60 минут, одна-две
задачи при интервьюере. Интервьюер оценивает восемь действий:

1. Понять условие.
2. Задать уточняющие вопросы.
3. Привести примеры входа и выхода.
4. Предложить решение перебором (brute force).
5. Оптимизировать.
6. Написать код.
7. Проверить его на примерах.
8. Объяснить решение и его сложность.

Верный ответ может не пройти проверку: если решение не уложилось в лимит
времени, система ставит вердикт **TLE** (Time Limit Exceeded). Форма кода
подсказывает число операций, а ограничение на размер входа в условии
подсказывает, какое решение ожидается.

### Как устроен курс

Программа собрана по открытым требованиям работодателей: структуры данных,
техники решения и объяснение решения. Работа ведётся на Python 3.12, с Git
и запускаемыми тестами. Баллы набираются на протяжении всей дисциплины:
домашние работы, тесты, mock-интервью, контест, разбор чужого кода.
ИИ разрешён на тренировке после собственной попытки; на диагностике,
mock-интервью, контестах и экзамене он закрыт.

## Термины

| Термин | Значение |
|---|---|
| алгоритм | конечная последовательность однозначных действий, которая превращает входные данные в нужный результат |
| инвариант | утверждение, которое остаётся верным на каждом шаге цикла; через него объясняют, почему решение верное |
| структура данных | способ хранения данных, от которого зависит цена операций: список, множество, словарь, куча, граф |
| brute force | полный перебор: проверить все варианты, ничего не сокращая |
| сложность | как растёт число операций при росте входа; записывается как O(n), O(n²), O(log n) |
| TLE | вердикт проверяющей системы: ответ верный, но решение не уложилось в лимит времени |
| краевой случай | вход на границе допустимого: пустой список, один элемент, дубликаты, отсутствие ответа |
| mock-интервью | репетиция алгоритмической секции на занятии с таймером и разбором |
| complexity note | короткая заметка к решению: время, память, худший случай |
| Pull Request | предложение изменений в репозитории с описанием подхода; его читают и комментируют до принятия |
